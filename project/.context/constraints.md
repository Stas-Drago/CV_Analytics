# Ограничения и запреты для ИИ-разработчика

## Неприкосновенные данные и безопасность

- Не читать, не выводить, не коммитить и не копировать URL камер, токены, API keys, cookies, headers, видео, снимки, SQLite/Qdrant runtime data за пределы согласованной среды.
- Не изменять `qdrant_data/`, `.db`, `logs.md`, веса моделей или recordings вручную. Любая миграция данных — отдельный утверждённый план с backup и rollback.
- Не удалять, перезаписывать, ротировать или тестировать реальные camera sources без явного разрешения владельца.
- Не открывать сервис на `0.0.0.0`, не отключать TLS/auth, не добавлять debug endpoint или CORS `*` для удобства разработки.
- Не логировать request headers, request body, prompt с персональными данными, URI с секретом и полный LLM context.

## Границы продукта

- Система — помощник оператора, а не автономный охранник. Она не принимает решения о санкциях, доступе, личности или правонарушении.
- Нельзя реализовывать распознавание лиц, биометрическую идентификацию, поведенческий скоринг или вывод «подозрительный человек» без отдельного письменного согласования, DPIA/юридической оценки и quality validation.
- Нельзя заявлять, что событие произошло, если этого нет в кадре/достоверном event source. Использовать «модель наблюдает/не может подтвердить».
- RAG не заменяет SQL/первичный источник: не отвечать без ID события, камеры и времени, если вопрос касается истории.

## Технические ограничения

- Не добавлять новые зависимости, внешние SaaS, GPU-образы или менять embedding/LLM/YOLO модель без согласования стоимости, лицензии, privacy и capacity.
- Не менять размерность/модель embeddings в существующей Qdrant collection; только новая collection и controlled reindex.
- Не переносить камеры, DB или Qdrant из localhost/внутренней сети во внешний интернет без сетевого дизайна и secret management.
- Не запускать модель, capture threads, регистрацию сервиса или миграции на import. Для этого нужны явные lifecycle команды.
- Не делать «быстрые» исправления через global locks, shared dictionaries или бесконечные retries; требуются очередь, timeout, healthcheck и наблюдаемая деградация.

## Изменения, требующие явного подтверждения

- Смена/ротация секретов и камерных URL, изменение networking/ports/firewall.
- Изменения схемы БД/коллекции, backfill/reindex и retention/deletion production данных.
- Model deployment или prompt change, которые могут менять пользовательские ответы.
- Любые внешние HTTP POST, регистрация сервиса и публикация артефактов.

## Что ИИ-разработчик обязан делать всегда

- Сначала изучать эти файлы `.context/` и существующие тесты/configuration.
- Перед изменением сообщать допущения и границы влияния; сохранять чужие незакоммиченные изменения.
- Добавлять тест вместе с bugfix, обновлять архитектурный документ при изменении контракта/потока.
- Останавливаться и запрашивать решение при конфликте требований, отсутствии данных для безопасного выбора или расширении scope.
